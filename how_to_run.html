Mapping sugarcane burning A run-it-yourself guide for the Si Chomphu hotspot pipeline

Area Si Chomphu, Khon Kaen Window 1 Dec 2025 – 5 May 2026 Sensor VIIRS · 375 m Crop layer GISTDA sugarcane

Everything below runs on your machine — it needs internet and the Python libraries. Two markers tell you what's mandatory: orange = required, green = optional. Follow them in order.

01

Install Python & the libraries required

Use Python 3.10+ . Put firms_sichomphu.py, requirements.txt, and run.sh together in one folder, open a terminal there, then install:

pip install -r requirements.txt

If pip fights you on geopandas (it pulls in GDAL), use conda instead:

conda install -c conda-forge geopandas folium requests pandas
02

Get the API keys you'll use free sign-ups

FIRMS MAP_KEY — only if you'll pull hotspots live (Route B in Step 3). Free at firms.modaps.eosdis.nasa.gov/api/area.

GISTDA key — only if you want the script to fetch the sugarcane layer for you (Step 4). Free at api-gateway.gistda.or.th/v2. Both keys are yours — paste them only into your own terminal, and use your own GISTDA key, not the demo key printed on the data catalog.

03

Get the hotspot data required

Pick one route. For a fixed past window like yours, Route A is the reliable choice — the archive tool serves science-quality data where ready and fills the most recent weeks automatically.

Route A · recommended

Archive download → file mode

Open the FIRMS archive tool, draw your area, set 2025-12-01 → 2026-05-05, choose VIIRS (S-NPP, NOAA-20, NOAA-21), export CSV. Save it next to the script as firms_archive.csv.

Route B · automation

Live API mode

No download clicks — the script pulls everything itself using your MAP_KEY. Best when you'll re-run this each season. Note: the newest weeks may need the NRT sources added in the script.

04

Choose the sugarcane filter optional but recommended

A hotspot only says something burned here — not the crop. To keep only sugarcane burns you overlay a sugarcane parcel layer. You don't have to source it by hand: the script can pull it from GISTDA, whose satellite sugarcane map (40 m, refreshed every two weeks) is openly licensed. Three ways to handle this step:

auto · best

Pass --gistda-key YOURKEY and the script queries GISTDA's search-by-geometry endpoint for the district, building sugarcane_gistda.geojson automatically.

own file

Already have polygons? Pass --sugarcane sugarcane.gpkg and it wins over GISTDA. Note: OCSB's open portal only has province-level area statistics, not parcels — its plot layer is request-only, so GISTDA is the practical polygon source.

skip

Pass neither. You still get every district hotspot — just not split by crop.

05

Run it required

The Si Chomphu boundary downloads automatically, so you never supply it. Route A + GISTDA sugarcane (the common case):

python firms_sichomphu.py --mode file --in firms_archive.csv --gistda-key YOURKEY

Route B (live hotspots, with your own sugarcane file):

python firms_sichomphu.py --mode api --map-key FIRMSKEY --sugarcane sugarcane.gpkg

Or just edit the variables at the top of run.sh and:

bash run.sh

Handy extras: --min-conf n keeps nominal+high confidence, --min-frp 1 drops the faintest detections, --out-prefix sichomphu_2526 names the outputs.

07

Open in QGIS for real maps finishing

Drag the .gpkg files into QGIS for cartography, kernel-density (heatmap) surfaces, or per-tambon counts. The summary.csv drops straight into a chart for the burning-season curve.

Read before you conclude

  • VIIRS over MODIS. 375 m vs 1 km — sugarcane plots are small, so the script defaults to VIIRS. MODIS would miss many fields.
  • Match the sugarcane layer to the season. GISTDA's map is 2-weekly, so the plots it returns reflect a recent snapshot — fine for a crop mask, but it isn't a frozen record of every field that existed each burn day.
  • Persistent same-spot hotspots across many dates are usually a sugar mill or other industrial heat source, not field burning. Inspect before counting them.
  • SP lags NRT. Science-quality data trails observation by ~2–3 months (up to 5). For the newest weeks in API mode, add the NRT sources and let dedup merge them.
  • A pixel is a detection, not a fire outline. Treat counts as relative intensity, not exact burned area.
